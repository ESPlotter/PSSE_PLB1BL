# PSS/E LPB LOAD model LPB1BL: repository guide

## Purpose

This repository delivers `LPB1BL`, a coordinated PSS/E load characteristic. The model replaces the static load of a bus with the active and reactive demand read from an external `.lpb` table, and passes each component through an optional first-order lag.

It is a delivery repository. The model is built and validated elsewhere, and every file here comes from that build.

## Layout

- `libraries/v<version>/LPB1BL_v<version>.dll`: compiled model for PSS/E 33, 34, 35, 36. These are binary deliverables. Never rebuild, rename or replace them.
- `fortran/`: Fortran sources of the delivered DLLs, provided for reference:
  - `LPB1BL.f`, used for every PSS/E version except 36;
  - `LPB1BL_VINDP.f`, the PSS/E 36 `PSSDM` interface source.
- `sample_case/`: three-bus case. It contains:
  - `lpb_load_bench.sav`;
  - `LPB1BL.dyr`;
  - `sample.lpb`, the sample demand table;
  - `Flat.plb`, the flat slack profile;
  - `Vsteps.plb`, the slack voltage steps of the `voltage_steps` validation scenario.
- `examples/run_lpb_load_example.py`: example simulation and VAR access. It runs under Python 2.7 and 3.
- `report/LPB1BL_validation_report.pdf`: validation report, built from `sample_case/sample.lpb`.
- `MANIFEST.json`: model data and SHA-256 of every delivered file.
- `output/`: created by the example. It is ignored by Git.

## Model facts

- **Internal names:** `LPB1BL` (main entry) and `TPB1BL` (network entry). A `USRLOD` with `IT=1` needs a six-character name ending in `BL`. Use `LPB1BL` in the DYR record and in `change_ldmod_*` calls.
- **ICONs:**
  - ICON 1 and 2 enable the table for P and Q.
  - ICON 3 is the table name, without `.lpb`.
- **CONs:** CON 1 (`Tfp`) and CON 2 (`Tfq`) are the lag time constants in seconds. A constant below `4*DELT` bypasses its lag.
- **VARs:** there are eight, in system per unit unless stated otherwise.
  - L, L+1: initial P and Q.
  - L+2, L+3: previous lag outputs.
  - L+4, L+5: current lag outputs.
  - L+6: previous instant.
  - L+7: current instant, which holds a negative marker until the table takes over.
- **Table file:** the `.lpb` and `.plb` files are read from the PSS/E working directory. The example changes to `sample_case/` before loading the case.
- **LPB format:** each nonblank line holds `time_s P_MW Q_Mvar`. Fields may be separated by spaces, commas or both. Times must be strictly increasing, and decimals use a point.
- **Requested vs. delivered power:** `PLOAD` and `QLOAD` channels report the demand requested by the model. To confirm the network actually supplies it, compare against the branch flow into the load bus.

## Working rules

- Do not edit files under `libraries/`, `fortran/` or `report/`. They are regenerated by the build process. Report problems instead of patching them.
- When changing the sample case or the example, keep the DYR model name equal to `LPB1BL` and keep the DLL path in the example consistent with `MODEL_NAME`.
- Describe changes to delivered files clearly so users can identify what changed.
- Run the example with the Python interpreter that belongs to the selected PSS/E version:

```powershell
python examples\run_lpb_load_example.py --psse-version 35
```
